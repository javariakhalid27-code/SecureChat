How Encryption
Actually Works

A step-by-step breakdown of how SecureChat encrypts every message using AES-256 and RSA-2048 to ensure only the intended recipient can read it.

// STEP BY STEP

The Encryption Process

01
USER REGISTERS — RSA KEYS GENERATED

When a new user registers, the server automatically generates a unique RSA-2048 key pair. The public key is stored and shared with other users. The private key is stored securely and never transmitted.

# RSA-2048 key pair generation
private_key = rsa.generate_private_key(
  public_exponent=65537,
  key_size=2048
)
public_key = private_key.public_key()
02
AES-256 SESSION KEY GENERATED

When sending a message, a random 256-bit AES session key is generated. This key is unique for every single message, ensuring perfect forward secrecy.

# Random AES-256 session key
aes_key = os.urandom(32) # 256 bits
iv = os.urandom(16)  # Random IV
# New key generated per message!
03
MESSAGE ENCRYPTED WITH AES-256

The plaintext message is encrypted using AES-256-CFB mode with the session key and random IV. The result is unreadable ciphertext that can only be decrypted with the correct key.

# AES-256-CFB encryption
cipher = Cipher(AES(aes_key), CFB(iv))
ciphertext = cipher.encrypt("Hello!".encode())
# Output: gX9kL2mN8pQrS4tU...
04
AES KEY WRAPPED WITH RSA-2048

The AES session key is encrypted using the receiver's RSA-2048 public key with OAEP padding. Now only the receiver's private key can unwrap the AES key.

# RSA-OAEP key wrapping
encrypted_key = receiver_public_key.encrypt(
  aes_key,
  OAEP(SHA256())
) # Only receiver can decrypt!
05
CIPHERTEXT TRANSMITTED

The encrypted message and RSA-wrapped AES key are sent to the server and forwarded to the receiver. The server only sees ciphertext — it cannot read the message.

# Server stores only encrypted data
message = Message(
  encrypted_message=ciphertext,
  encrypted_key=rsa_wrapped_key
) # Zero plaintext!
06
RECEIVER DECRYPTS — READS MESSAGE

The receiver uses their RSA private key to unwrap the AES session key, then uses that AES key to decrypt the ciphertext. The original message is recovered — only by the intended recipient.

# Receiver decryption
aes_key = private_key.decrypt(encrypted_key)
plaintext = aes_decrypt(ciphertext, aes_key)
# Output: "Hello!" — Only receiver!

// FAQ

Common Questions

CAN THE SERVER READ MY MESSAGES?▼
No. The server only stores encrypted ciphertext. Without the receiver's private RSA key, the ciphertext is mathematically impossible to decrypt. This is true end-to-end encryption.
HOW STRONG IS AES-256?▼
AES-256 has 2²⁵⁶ possible keys. Even if every computer on Earth tried one trillion keys per second, it would take longer than the age of the universe to crack. It is the standard used by governments and militaries worldwide.
WHAT IS RSA-2048 USED FOR?▼
RSA-2048 is used for key exchange, not message encryption. The AES-256 session key is wrapped (encrypted) using the receiver's RSA public key. Only their RSA private key can unwrap it, making the AES key accessible only to the intended recipient.
HOW ARE PASSWORDS STORED?▼
Passwords are never stored in plaintext. They are hashed using bcrypt with a unique random salt. bcrypt is an adaptive hashing algorithm designed specifically for passwords, making brute force attacks computationally expensive.
IS EVERY MESSAGE UNIQUELY ENCRYPTED?▼
Yes. A new random AES-256 session key and random IV (Initialization Vector) are generated for every single message. This means even if two identical messages are sent, their ciphertexts will be completely different.
